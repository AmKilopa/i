# Klpfetch v0.0.1

Нативная система удалённого мониторинга компьютера. На ПК работает агент, на ноутбуке открывается полноэкранная интерактивная панель в Windows Terminal.

## Что уже показывает

- загрузку CPU и память;
- диски и свободное место;
- скорость сетевого трафика;
- NVIDIA GPU, видеопамять и температуру при доступном `nvidia-smi`;
- ОС, процессор и состояние соединения.

Интерфейс выполнен в стиле neofetch: часы с крупными секундами находятся строго по центру, слева показаны `SYSTEM` и `RESOURCES`, справа — `HARDWARE` и `NETWORK`. Ресурсы отображаются сегментными градиентными шкалами. Вкладок, списка процессов, графиков и переключателя темы нет. Выход — `q` или `Esc`.

## Проверка на одном компьютере

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Start-Local-Test.ps1
```

Скрипт запускает агент скрыто только на время проверки, открывает dashboard и гарантированно останавливает агент после выхода.

Для локальной проверки токен вводить не нужно: тестовый скрипт передаёт временный общий секрет обоим приложениям сам.

## Сборка

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Build-Release.ps1
```

Готовые файлы появятся в `dist\PC` и `dist\Laptop`.

## Запуск между ПК и ноутбуком

Один постоянный токен можно сгенерировать командой:

```powershell
.\Generate-Token.ps1
```

Это случайная строка, а не токен от сайта или аккаунта. Одну и ту же строку нужно указать на ПК и ноутбуке.

На ПК:

```powershell
.\Start-Agent-Lan.ps1 -Token 'замените-на-длинный-общий-токен'
```

После проверки агент можно запустить без видимого окна:

```powershell
.\Start-Agent-Lan.ps1 -Token 'замените-на-длинный-общий-токен' -Hidden
```

На ноутбуке:

```powershell
.\Start-Dashboard-Fullscreen.ps1 -Computer '192.168.1.50' -Token 'тот-же-самый-длинный-токен'
```

Для полноэкранного режима используется Windows Terminal `wt.exe -F`. Параметр `-Maximized` открывает обычное развёрнутое окно вместо режима F11.

Агент по умолчанию доступен только через `127.0.0.1`. Для LAN он требует токен минимум из 12 символов. Автозапуск пока намеренно не устанавливается: сначала нужно проверить соединение и выбрать постоянный адрес ПК.

Текущая версия рассчитана на доверенную домашнюю LAN: WebSocket защищён токеном, но пока не шифруется TLS. Порт нельзя открывать напрямую в интернет. Перед передачей файлов будет добавлено локальное pairing-подключение с шифрованием.

## Протокол

- health: `GET /health`;
- разовый снимок: `GET /api/v1/snapshot`;
- поток: `WS /api/v1/stream`;
- авторизация: `Authorization: Bearer <token>`;
- управление: `terminate_process` через авторизованный WebSocket с подтверждением в интерфейсе;
- текущая версия протокола: `1`.

Разделение протокола и интерфейса оставляет место для безопасного добавления передачи файлов отдельным каналом.
